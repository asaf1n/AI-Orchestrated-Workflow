# Привязка проекта

Навыки `planner`, `orchestrate`, `implementer`, `reviewer` установлены в общем профиле и вызываются по имени. Общий протокол читается из установленного `orchestrate/SKILL.md`, подключение и формы задания — из его `references/` (`connection.md`, `stage-forms.md`); формы плана, результата и заключения — из `SKILL.md` соответствующих ролей. В проект они не копируются.

Этот файл задаёт проектные пути и отклонения. Оркестратор создаёт только необходимые проекту файлы по общему навыку; существующие инструкции сохраняет. При выполнении явно запущенного утверждённого плана после независимой приёмки коммитит этап и переходит к следующему без повторного вопроса, кроме новых условий или конфликтов. Явные ограничения пользователя сохраняются, push согласуется отдельно. Ответ этапа: блок 1 — «Как сейчас» → таблица «№ | что | как» → «Нужно ваше решение»; блок 2 — предметная вики-сводка в Textile для учёта трудозатрат в Redmine (архитектура, логика, DWH, DAG, тесты; без истории переписки, моделей и личных git) по шаблону общего навыка.

## Пути проекта

| Назначение | Место |
|---|---|
| Контракт проекта | `AGENTS.md` |
| Корень workflow | `orchestrate_workflow/` |
| Очередь и статус плана | `orchestrate_workflow/plans/<план>/00_summary.md` |
| Материал задачи и состояние этапов | `orchestrate_workflow/plans/<план>/<задача>.md` |
| Действующее задание | `orchestrate_workflow/<план>/spec.md` |
| Отчёт исполнителя | `orchestrate_workflow/<план>/result.md` |
| Независимое ревью этапа | `orchestrate_workflow/<план>/review.md` |
| Ревью плана или инструкций | `orchestrate_workflow/<план>/review_plan.md` |

`orchestrate_workflow/plans/` хранится в git. Каталог текущей сессии `orchestrate_workflow/<план>/` локальный и исключается по точному пути `/orchestrate_workflow/<план>/` через `.git/info/exclude`. Имя `plans` зарезервировано и не используется как имя плана.

Файлы выбираются только по точным путям и явным ссылкам. Task-файлами считаются только файлы, на которые ссылается `00_summary.md`. В каталоге текущей сессии протокольными являются только `spec.md`, `result.md`, `review.md`, `review_plan.md`; связанные исходники, зависимости и документация читаются по необходимости проверки в границах поручения.

## Проектные отклонения

Нет. Предметные источники, допустимые изменения и проверки определяет `AGENTS.md` и текущее задание этапа.
