# Привязка проекта

Общие роли и цикл задаёт комплект навыков: planner, orchestrate, implementer, reviewer. Единственный общий протокол — `~/.agents/skills/orchestrate/references/protocol.md`. Отметки версии этапа и проверок — `references/runtimes.md`, запуск сессии по имени плана — `references/session-start.md`. Этот файл задаёт пути проекта и не повторяет протокол. Если комплект недоступен, назови отсутствующий путь и не собирай процесс по старым отчётам.

## Где находится состояние

| Назначение | Место |
|---|---|
| Очередь плана и ссылки | `plans/<план>/00_summary.md` |
| Цель, решения, этапы, критерии и единственное состояние этапов | `plans/<план>/<задача>.md`, раздел «Этапы задачи» |
| Единственное действующее задание | `orchestrate_workflow/<план>/spec.md` |
| Отчёт исполнителя и независимое ревью | `orchestrate_workflow/<план>/result.md`, `review.md` |

Файлы в корне `orchestrate_workflow/` — метод, их правит оркестратор. Каталоги обмена пишут роли. Эти каталоги исключены из git:

```gitignore
/orchestrate_workflow/*/
```

Имена существующего плана не меняются. Материалы закрытых задач остаются на своих путях. Локальный обмен перезаписывается и в git не входит. Отдельный локальный план и копии заданий не ведутся. Утверждённые решения не остаются только в чате.

## Роли и запуск

Оркестратор вызывается явно. Планировщик готовит или существенно пересматривает план; независимый ревьювер проверяет его до утверждения. Утверждение и команда запуска различаются. Запуск разрешает исполнение утверждённых этапов и коммиты после приёмки, если команда их не ограничила. Push разрешается отдельно.

Все роли наследуют текущую модель. Исполнитель и ревьювер получают новый контекст. Один исполнитель работает над одним этапом. Инструкции и материалы плана правит оркестратор; такие изменения тоже проходят независимое ревью.

Перед новым этапом нужна чистая исходная точка. Чужие правки не удаляются, не прячутся и не коммитятся. Восстановление начатого этапа сначала устанавливает принадлежность изменений. Конец вызова или старый отчёт приёмку не подтверждают.

Ревью обязательно для каждого этапа. Эталон приёмки, ослабление критериев, исключения, возврат и приёмка после возврата — по протоколу, разделы «Проверки и приёмка» и «Текущие файлы и возврат». Результат принятого этапа и его состояние фиксируются одним коммитом.

## Предметная работа

Контракт проекта — `AGENTS.md`. Перед вопросом или новым правилом читаются соответствующее описание и действующее решение. Короткая реплика не разрешает дополнительную бизнес-логику. Задание не меняется одновременно с исполнением: сначала устанавливается безопасная точка продолжения.

Отказ инструмента сообщается по разделу «Отказы среды» протокола. Настройки разрешений ради обхода отказа не меняются.

Для проверки среды обязательны конкретные критерии. Если задана визуальная проверка, ответ API и текст страницы её не заменяют. Известные падения называются по проверке и причине.

Шаблоны — в общем комплекте, `references/templates.md`. Восстановление сессии — `references/session-start.md`.
