# AI-Orchestrated Workflow

Четыре навыка для Claude Code, Codex и Antigravity: подготовка плана, ведение этапов, исполнение и независимое ревью. Источник истины — этот репозиторий. Инструкции и формы ролей находятся в их `SKILL.md`; тематические материалы оркестратора вынесены в `skills/orchestrate/references/` и читаются только им.

| Навык | Назначение |
|---|---|
| [orchestrate](skills/orchestrate/SKILL.md) | Управление процессом и состоянием; модели, вызовы, подключение проекта, формы задания и итога этапа — в `references/`. Другие роли читают собственные навыки. |
| [planner](skills/planner/SKILL.md) | Подготовка и пересмотр плана, формы очереди и материала задачи. |
| [implementer](skills/implementer/SKILL.md) | Исполнение одного этапа и форма result.md. |
| [reviewer](skills/reviewer/SKILL.md) | Независимое ревью этапа, плана и инструкций; формы заключений. |

## Установка и обновление

После независимого ревью исходников перенесите четыре каталога skills в фактические глобальные каталоги обнаружения используемых сред. Codex и общий профиль используют `~/.agents/skills`; Claude Code — `~/.claude/skills`; Antigravity IDE — `~/.gemini/config/skills`; Antigravity CLI — `~/.gemini/antigravity-cli/skills`. Проверьте обнаруженный путь и реальное чтение навыка; версия инструмента и его настройки могут влиять на обнаружение. [Каталоги Antigravity](https://antigravity.google/docs/skills/), [навыки Claude Code](https://code.claude.com/docs/en/skills).

На Windows для первоначальной установки из корня репозитория:

```powershell
$workflowSkillRoots = @(
    (Join-Path $env:USERPROFILE '.agents/skills'),
    (Join-Path $env:USERPROFILE '.claude/skills'),
    (Join-Path $env:USERPROFILE '.gemini/config/skills'),
    (Join-Path $env:USERPROFILE '.gemini/antigravity-cli/skills')
)
foreach ($workflowSkillRoot in $workflowSkillRoots) {
    New-Item -ItemType Directory -Force -Path $workflowSkillRoot | Out-Null
    foreach ($workflowRole in 'orchestrate', 'planner', 'implementer', 'reviewer') {
        Copy-Item -LiteralPath "skills/$workflowRole" -Destination $workflowSkillRoot -Recurse -Force
    }
}
```

Для обновления сначала сравните установленные файлы с актуальными исходниками и сохраните локальные дополнения. Переносите проверенную версию SKILL.md, каталога references/ (у orchestrate) и изменённых помощников, сохраняя пользовательские agents/openai.yaml и настройки. Удалите проверенные устаревшие references и исправьте ссылки; простое Copy-Item не удаляет старые файлы и может перезаписать метаданные. Сверьте SHA-256 после установки и повторного переноса. Новые вызовы выполняются в новом контексте.

Claude Code может требовать разрешения Read для комплекта вне workspace. Наличие allow не доказывает чтение: выполните реальный проверочный вызов без записи и проверьте ответ, stderr и код выхода. Авторизация, секреты и разрешения не изменяются ради обхода отказа.

## Использование

В Codex команда начинается с `$orchestrate`; в Claude и Antigravity — с `/orchestrate`, если навык обнаружен. При первом подключении можно явно поручить прочитать глобальный SKILL.md. Проектная привязка — одна orchestrate_workflow/method.md; общие инструкции и формы в проект не копируются.

```text
$orchestrate Создай план <имя>. Цель: <результат>. Исполнение не запускай.
$orchestrate Запусти утверждённый план <имя>. Push запрещён.
$orchestrate Продолжи запущенный план <имя>. Сначала сверь материал, git, отчёты и процессы.
$orchestrate Доложи подтверждённое состояние плана <имя>. Исполнение не запускай.
```

Новый план и существенный пересмотр проходят независимое ревью и утверждение. Подготовка и согласие с планом сами по себе исполнение не запускают. Явно запущенный утверждённый план включает фиксацию принятых этапов и переход к следующему без повторного вопроса; запрет коммитов сохраняется, push разрешается отдельно.

Исполнитель и ревьювер работают в новых контекстах. У каждого участника определены файлы и общие ресурсы. Независимые исследования допускают параллельность; изменение общей БД, схемы и проверка зависимого состояния согласуются по владельцу ресурса. Отдельный worktree не изолирует сервисы.

Поставщик, уровень модели, уровень рассуждений, runtime и канал квоты различаются. Встроенный Claude через Antigravity не равен внешнему Claude Code по каналу подписки. Модель и уровень рассуждений задаются параметрами runtime; фактическая модель подтверждается метаданными ответа (уровень рассуждений — если runtime возвращает его в метаданных или идентификаторе профиля), а текст «от лица Astra» не является запросом к этой модели. Полные правила выбора, альтернатив и доказательств находятся в [models.md](skills/orchestrate/references/models.md).

В examples находятся тонкие определения ролей и пример проектной привязки. Проектных копий навыка orchestrate нет: он вызывается напрямую из глобального каталога. Определения ролей вызывают установленный комплект и не содержат второй протокол. Обновление не запускает продуктовые планы и не принимает результаты прошлых этапов.

## Текущие CLI и модели

Поддерживаемые среды: Codex, Claude Code и Antigravity. Модели разделены на две очереди с явными уровнями усилий (`low`, `medium`, `high`, `xhigh`): старшие (Tier 1) и основные исполнители (Tier 2). Конкретные идентификаторы берутся из актуального каталога среды (`agy models`, настройки Codex и Claude Code; [официальный список моделей Antigravity](https://antigravity.google/docs/models)).

| Очередь / Модель | Поставщик и среды | Уровни усилия | Целевое использование |
|---|---|---|---|
| **Tier 1 (Старшие)** ||||
| Opus | Anthropic (Claude Code, Antigravity) | `medium`, `high`, `xhigh` | Архитектура, проектирование и ТЗ высокой неопределённости, существенные контракты, арбитраж; `xhigh` — при сохраняющейся сложности |
| Astra | OpenAI (Codex) | `medium`, `high`, `xhigh` | Сложный рефакторинг, оценка архитектурных решений, арбитраж и кросс-вендорное ревью |
| Argon | Google (Antigravity) | `medium`, `high` | Архитектурные оценки, кросс-вендорный арбитраж, сложные регламенты; `xhigh` не предполагается |
| **Tier 2 (Исполнители)** ||||
| Sol | OpenAI (Codex) | `medium`, `high` | Основная инженерная реализация: код, SQL/PL-pgSQL, тесты, конфиги, рефакторинг; `high` — при заранее известных нетривиальных инвариантах |
| Flash | Google (Antigravity) | `low`, `medium`, `high` | Нативный исполнитель Antigravity: разведка, сбор контекста, материалы, документация, типовые локальные правки; `low` — извлечение |
| Sonnet | Anthropic (Claude Code, Antigravity) | `medium`, `high` | Реализация и исправления по подготовленному заданию, сложная диагностика и длительные связанные изменения (`high`) |

### Базовые линии сценариев (Маршрутизация по типам задач)

1. **Архитектура, проектирование и ТЗ с высокой неопределённостью:** `Opus (high)` → `Astra (high)` → `Argon (high)`
2. **Основная инженерная реализация (код, SQL, тесты, конфиги, рефакторинг):** `Sol (medium)` → `Flash (medium)` → `Sonnet (medium)` (при сложных инвариантах старт с `Sol (high)`)
3. **Разведка, сбор контекста, обработка материалов и документация:** `Flash (medium/low)` → `Sol (medium)` → `Sonnet (medium)`
4. **Типовые локальные правки и независимые параллельные подзадачи:** `Flash (medium)` → `Sol (medium)` → `Sonnet (medium)`
5. **Штатное независимое ревью этапа:** `Opus (medium)` → `Astra (medium)` → `Argon (medium)` (`high` для изменений с существенными последствиями)
6. **Кросс-вендорное ревью и арбитраж (сложные решения / конфликт оценок):** после Opus ревьюит `Astra (high)` → `Argon (high)`; после Astra/Sol ревьюит `Opus (high)` → `Argon (high)`

> **Памятка перед стартом сессии в UI Antigravity:** выбирайте `Gemini 3.8 Flash (medium)` для штатного ведения проекта (оркестратор сам план не составляет, а управляет взаимодействием и процессом, делегируя задачи исполнителям) либо `Opus / Argon (high)` для сессий с глубоким интерактивным анализом и обсуждением архитектурных концепций с пользователем до постановки ТЗ планировщику.

Полные правила выбора моделей, допустимых замен, эскалации и доказательств находятся в [models.md](skills/orchestrate/references/models.md).
