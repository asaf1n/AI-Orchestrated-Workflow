# AI-Orchestrated Workflow

Мультивендорный протокол разработки с раздельными агентами планирования, реализации и независимого ревью под управлением Orchestrator. Работает через Claude Code, Codex, Google Antigravity и дополнительные CLI. Orchestrator управляет процессом и передаёт продукт ролям; сам вносит только механические правки текста.

| Навык | Ответственность |
|---|---|
| [orchestrate](skills/orchestrate/SKILL.md) | Маршрутизация ролей, моделей, runtime, передача контекста и сборка результата |
| [planner](skills/planner/SKILL.md) | План, задачи, критерии завершения |
| [implementer](skills/implementer/SKILL.md) | Один этап, проверки и результат |
| [reviewer](skills/reviewer/SKILL.md) | Независимая оценка плана, инструкций или результата |

Для сложной работы Planner готовит план, Implementer выполняет, Reviewer независимо оценивает содержательные результаты. Внутренние мелкие шаги не создают обязательных повторных циклов ревью. План в Git нужен для многошаговой работы; локальные `state.md`, `spec.md`, `result.md`, `review.md` и слоты `runs/<id>/` используются только когда помогают передаче, восстановлению или изоляции параллельных задач. Пользователь утверждает существенный план и изменение его цели/объёма, а не каждую техническую корректировку. После запуска работа продолжается без повторных запросов разрешения до блокера. Коммиты делает Orchestrator в разрешённых границах; push — по отдельному разрешению.

## Установка

Установите четыре каталога из `skills/` в фактический каталог навыков среды:

| Runtime | Глобальные навыки |
|---|---|
| Codex / общий профиль | `~/.agents/skills/` |
| Claude Code | `~/.claude/skills/` |
| Antigravity App, IDE и agy | `~/.gemini/config/skills/` |

Проектные навыки Antigravity можно расположить в `.agents/skills/`. Не создавайте второй глобальный комплект для agy. Перед установкой сравните текущие файлы и сохраните пользовательские дополнения; порядок обновления — в [kit-update.md](skills/orchestrate/references/kit-update.md). Для запуска в уже открытой сессии заново прочитайте установленный навык.

Обновление определений ролей и глобальных инструкций выполняется только в порученной области. Их пути, сохранение пользовательских метаданных и порядок сверки описаны в [kit-update.md](skills/orchestrate/references/kit-update.md). Проектный `AGENTS.md` не заменяет глобальный контракт пользователя.

## Запуск

В Codex — `$orchestrate`; в Claude Code и Antigravity — `/orchestrate`:

```text
/orchestrate Создай план <имя>. Цель: <результат>. Исполнение не запускай.
/orchestrate Запусти утверждённый план <имя>. Push запрещён.
/orchestrate Продолжи план <имя>. Сверь Git, отчёты и активные процессы.
/orchestrate Доложи состояние плана <имя>. Исполнение не запускай.
```

Привязка проекта: `orchestrate_workflow/method.md`; образец в [examples/project](examples/project/orchestrate_workflow/method.md). Она задаёт проектные пути, границы, проверочные команды и при необходимости закреплённые поставщиков или runtime — без копирования общего протокола.

Модель подбирается по роли, возможностям, доступности и требованиям к независимости; смена модели и настройка `effort` применяются только если их поддерживает выбранный runtime (для управляемых и фиксированных профилей, например Docker AI, они не обязательны). Поддерживаются также опциональный CLI `docker agent` (включая локальные модели Docker Model Runner) и контейнерные инструменты (`docker scout`, `docker dhi`, `docker compose bridge`, `docker mcp gateway`). Для управления сессией Antigravity из внешнего LLM-чата есть опциональный [MCP-мост](bridge/README.md). Текущие имена и параметры проверяются в runtime, а не зашиваются в навыки. Подробности: [models.md](skills/orchestrate/references/models.md) и [external-calls.md](skills/orchestrate/references/external-calls.md).

## Ограничения

Независимый Reviewer работает в отдельном контексте и не исправляет продукт. Git worktree изолирует файлы, но не БД, сервисы и порты.
