# AI-Orchestrated Workflow

Общий протокол разработки с разделением планирования, исполнения, независимого ревью и управления состоянием. Работает через навыки Claude Code, Codex и Google Antigravity. Конкретные модели, версии, среда вызова и предметные требования проекта не входят в постоянные правила.

| Навык | Ответственность |
|---|---|
| [orchestrate](skills/orchestrate/SKILL.md) | Единственный владелец состояния плана и назначений ролей |
| [planner](skills/planner/SKILL.md) | План, задачи, критерии завершения |
| [implementer](skills/implementer/SKILL.md) | Один этап, проверки и результат |
| [reviewer](skills/reviewer/SKILL.md) | Независимая оценка плана, инструкций или результата |

План и решения хранятся в Git. Файлы текущего исполнения `spec.md`, `result.md`, `review.md` и `review_plan.md` локальны. Новое планирование и значимые изменения проходят ревью и утверждение пользователя; согласие с планом не запускает исполнение. Запущенный утверждённый план выполняется по этапам до блокера или завершения, без повторного запроса согласия. Коммит принятого этапа выполняет оркестратор; push только по отдельному разрешению.

## Установка

Установите четыре каталога из `skills/` в фактический каталог навыков среды:

| Runtime | Глобальные навыки |
|---|---|
| Codex / общий профиль | `~/.agents/skills/` |
| Claude Code | `~/.claude/skills/` |
| Antigravity App, IDE и agy | `~/.gemini/config/skills/` |

Проектные навыки Antigravity можно расположить в `.agents/skills/`. Не создавайте второй глобальный комплект для agy. Перед установкой сравните текущие файлы и сохраните пользовательские дополнения; установку и SHA-256 проверьте по [kit-update.md](skills/orchestrate/references/kit-update.md). Для запуска в уже открытой сессии заново прочитайте установленный навык.

## Запуск

В Codex — `$orchestrate`; в Claude Code и Antigravity — `/orchestrate`:

```text
/orchestrate Создай план <имя>. Цель: <результат>. Исполнение не запускай.
/orchestrate Запусти утверждённый план <имя>. Push запрещён.
/orchestrate Продолжи план <имя>. Сверь Git, отчёты и активные процессы.
/orchestrate Доложи состояние плана <имя>. Исполнение не запускай.
```

Привязка проекта: `orchestrate_workflow/method.md`; образец в [examples/project](examples/project/orchestrate_workflow/method.md). Она задаёт проектные пути, границы, проверочные команды и при необходимости закреплённые поставщиков или runtime — без копирования общего протокола.

Модель подбирается по роли, возможностям, доступности и требованиям к независимости. Текущие имена и параметры проверяются в runtime, а не зашиваются в навыки. Подробности: [models.md](skills/orchestrate/references/models.md) и [external-calls.md](skills/orchestrate/references/external-calls.md).

## Внешний LLM-чат → Antigravity

Локальный [MCP-мост](bridge/README.md) принимает запросы от внешних LLM-клиентов и передаёт их в одну именованную сессию `agy`. Внешний клиент выступает заказчиком и корректором, Antigravity остаётся единственным оркестратором плана. Доступны инструменты `agy_dispatch_goal` и `agy_refine_session`; сессии регистрируются и восстанавливаются по `conversation_id`. Для удалённого подключения используется Streamable HTTP за аутентифицированным TLS-шлюзом. Запуск API не предоставляет внешнему клиенту доступ к оболочке напрямую.

## Ограничения

Независимый Reviewer работает в отдельном контексте и не исправляет продукт. Git worktree изолирует файлы, но не БД, сервисы и порты; общим ресурсам назначаются владельцы. Итог этапа подтверждается выполненными проверками, версией файлов и заключением Reviewer, а не текстом исполнителя.
