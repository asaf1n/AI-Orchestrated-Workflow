# AI-Orchestrated Workflow

Лёгкая оркестрация разработки для Claude Code, Codex и Google Antigravity. По умолчанию агент **выполняет задачу**, а не строит конвейер из планирования, ревью и отчётов.

| Навык | Когда нужен |
|---|---|
| [orchestrate](skills/orchestrate/SKILL.md) | Выбор способа выполнения, делегирование и сборка результата |
| [planner](skills/planner/SKILL.md) | Сложная декомпозиция или существенное изменение плана |
| [implementer](skills/implementer/SKILL.md) | Исполнение отдельной задачи |
| [reviewer](skills/reviewer/SKILL.md) | Независимая оценка по запросу или при значимом риске |

## Принцип работы

- **Простая задача:** изучить необходимое → изменить → проверить затронутое → сообщить результат.
- **Сложная задача:** краткий план → исполнение (с делегированием при пользе) → проверка. Планирование не обязано завершаться отдельным согласованием, если пользователь уже поручил реализацию и цель не меняется.
- **Ревью:** необязательный инструмент. Назначается по запросу пользователя либо при существенном риске ошибки (безопасность, необратимые операции, сложная миграция или архитектура). Замечания не порождают новые требования сами по себе.
- **Документация:** только необходимая для результата или передачи работы. Нет обязательных `spec/result/review` на каждый этап, SHA-256 всех файлов, отдельного контрольного набора и цикла повторных утверждений.
- **Оценка результата:** по цели пользователя, проектному контракту и существующим проверкам. Новые метрики и эталоны — только по предметному основанию и согласованной задаче.

План при необходимости хранится в `orchestrate_workflow/plans/<имя>/`; локальный `state.md` нужен только для длительного процесса, восстановления или передачи сессии. Существующие файлы прежнего формата можно читать, без миграции ради формы.

## Установка

Установите нужные каталоги из `skills/` в каталог навыков своей среды:

| Runtime | Каталог |
|---|---|
| Codex / общий | `~/.agents/skills/` |
| Claude Code | `~/.claude/skills/` |
| Antigravity IDE и agy | `~/.gemini/config/skills/` |

Дополнительные профили используют собственные каталоги. Сохраняйте пользовательские изменения: [инструкция по установке](skills/orchestrate/references/kit-update.md). Пример проектной привязки: [method.md](examples/project/orchestrate_workflow/method.md).

## Запуск

`/orchestrate Сделай <задачу>. Не создавай отдельный план и ревью без необходимости.`

`/orchestrate Спланируй <цель>, без исполнения.`

`/orchestrate Продолжи <план> с места остановки.`

В Codex вызов — `$orchestrate`. Роли и runtime выбираются по возможностям и доступу, а не по жёсткой цепочке: [models.md](skills/orchestrate/references/models.md), [external-calls.md](skills/orchestrate/references/external-calls.md).

## Внешний LLM-чат → Antigravity

[MCP-мост](bridge/README.md) передаёт запросы внешнего клиента в именованную сессию `agy`. Внешний чат уточняет цель, Antigravity владеет сессией; мост не выдаёт shell-доступ.

## Границы

Не изменяйте чужие файлы без основания; не отключайте разрешения среды. Для параллельных задач избегайте конфликтов файлов и общих ресурсов. Независимое ревью, формальные отчёты и расширенная трассировка включаются только тогда, когда их ценность превышает затраты.
