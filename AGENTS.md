# Контракт AI-Orchestrated Workflow

Этот репозиторий — источник истины для четырёх устанавливаемых навыков: `orchestrate`, `planner`, `implementer`, `reviewer`.

## Направление

- Цель — результат пользователя. Процедуры, файлы и проверки нужны, пока помогают этой цели, и не становятся целью сами.
- **Orchestrator** управляет процессом: роли, модели, runtime, каналы и момент передачи. Продукт и существо плана передаёт ролям; сам вносит только механические правки текста.
- **Planner** готовит план или его существенный пересмотр, **Implementer** реализует и проверяет, **Reviewer** независимо оценивает и не меняет проверяемое.
- Роли работают в новом контексте без истории разговора и сами выполняют проверки, нужные для своей задачи. Собственную оркестрацию они не запускают.
- Решения пользователя первичны. Снятое пользователем не возвращается; эталоны, метрики, пороги и новые стадии без предметного основания не вводятся. Замечание ценно, если указывает реальный дефект.
- Распределение ролей мультивендорное: Claude Code, Codex, Google Antigravity и другие runtime. Смена поставщика — по риску, а не в каждом вызове.

## Навигация

- `skills/orchestrate/SKILL.md` — управление workflow; `skills/orchestrate/references/` — модели, вызовы и инструменты, параллельная работа, подключение, установка, формы.
- `skills/planner/`, `skills/implementer/`, `skills/reviewer/` — работа ролей.
- `bridge/` — опциональный MCP-шлюз к сессии `agy`, со своими тестами.
- `examples/` — тонкие адаптеры runtime и пример привязки проекта.

## Изменения комплекта

Правило живёт в одном файле, остальные ссылаются на него. Тонкие адаптеры содержат только ссылку на навык и границы роли. Совместимость `spec.md`, `result.md`, `review.md` сохраняется. Документация — деловым русским языком. Для кода — тесты и `git diff --check`; полномочия шлюза не расширяй и разрешения runtime не отключай.

Изменения в Git — в порученной ветке. Push и слияние в целевых проектах — только по разрешению владельца.
