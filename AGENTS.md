# Контракт AI-Orchestrated Workflow

Этот репозиторий — источник истины для четырёх устанавливаемых навыков: `orchestrate`, `planner`, `implementer`, `reviewer`.

## Границы

- `skills/*/SKILL.md` — полномочия и формы ролей. Роли читают собственный навык, проектный контракт и источники задания, не весь протокол оркестратора.
- `skills/orchestrate/references/` — справочники оркестратора по моделям, вызовам, формам, ресурсам, подключению и обновлению; Reviewer читает их и `orchestrate/SKILL.md`, если они назначены объектом аудита, без передачи управления workflow.
- `bridge/` — шлюз для внешних LLM-клиентов. Он передаёт поручения в `agy`, но не реализует планирование или ревью.
- `examples/` — тонкие адаптеры и привязка проекта без копий протокола.

Протокольные поля и файлы `spec.md`, `result.md`, `review.md` сохраняют совместимость. При их изменении синхронизируй формы и описание ролей. Предметные требования, форматы отчётности и модели конкретного проекта определяются в его `AGENTS.md` и `orchestrate_workflow/method.md`, а не в этом комплекте.

## Проверка изменений

| Область изменений | Обязательный источник | Проверка |
|---|---|---|
| Управление workflow и вызовы | `skills/orchestrate/SKILL.md`, соответствующие `references/` | Независимое ревью окончательной версии, сверка ссылок |
| Планирование, исполнение, приёмка | `skills/planner/SKILL.md`, `skills/implementer/SKILL.md`, `skills/reviewer/SKILL.md` по роли | Согласованность границ ролей и форм, `git diff --check` |
| Проектные примеры | `examples/`, формы соответствующих навыков | Сверка путей и отсутствие копий общего протокола |
| Установка, определения ролей и глобальные инструкции | `README.md`, `skills/orchestrate/references/kit-update.md` | Независимое ревью до переноса, сохранение пользовательских отличий, SHA-256 целевых файлов |
| MCP-мост | `bridge/README.md` | Проверки по документации моста, сохранение границ разрешений |

Тонкие определения ролей (`.claude/agents/`, `.codex/agents/`, `.agents/agents/`) и проектные файлы (`CLAUDE.md`, `GEMINI.md`) содержат только ссылки на установленный навык и `@AGENTS.md`. Документация пишется деловым русским языком, чёткими инженерными формулировками, без жаргона и калек.

Изменения протокола проходят независимое ревью окончательной версии, проверку ссылок и согласованности ролей. Для кода запускай тесты и `git diff --check`; не расширяй полномочия шлюза и не отключай разрешения runtime. Проверка файлов не подменяет запуск полного цикла в установленных CLI. Факты проверок фиксируй отдельно от предположений.

Коммиты создаются в порученной ветке. Не сливай в main и не выполняй push в целевых проектах без прямого разрешения их владельца.
