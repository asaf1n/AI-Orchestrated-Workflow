# Контракт AI-Orchestrated Workflow

Этот репозиторий содержит четыре навыка: `orchestrate`, `planner`, `implementer`, `reviewer`. Цель — довести запрос пользователя до результата с минимально достаточными передачами управления, проверками и документацией.

## Приоритет

1. Явное решение пользователя и требования целевого проекта.
2. Факты из исходников, действующие тесты и реальные ограничения среды.
3. Рекомендации навыков — только если не добавляют к задаче незаказанные обязательства.

Не превращай предложения агента или замечания Reviewer в требования без основания в пп. 1–2. Не создавай собственных эталонов, порогов, банков вопросов, журналов, контрольных ворот и повторных испытаний без задачи пользователя или предметной необходимости.

## Роли

- Orchestrator выбирает кратчайший путь: выполняет простое сам либо делегирует сложное. Ведёт общий контекст и интеграцию.
- Planner нужен при реальной сложности декомпозиции или изменении цели/архитектуры.
- Implementer реализует ограниченное поручение.
- Reviewer используется по запросу или при существенном риске. Его замечания проверяются на соответствие реальным требованиям; они не расширяют задачу.
- Ведомые роли не создают вложенный конвейер агентов. При отдельном вызове передавай только релевантные материалы, а не историю разговора.

Файлы `skills/*/SKILL.md` задают поведение ролей, `skills/orchestrate/references/` — справочная информация по необходимости, `bridge/` — отдельный MCP-шлюз. Пример проекта не является обязательным шаблоном всех проектов.

## Проверка и изменения

Проверяй изменённое поведение применимыми средствами: целевым тестом, сборкой или прямой проверкой результата. Для правок Git — `git diff --check`, когда доступна локальная рабочая копия. Не повторяй уже достаточные проверки без изменившихся входов или конкретной причины. Незавершённое называй незавершённым.

Не затрагивай чужие изменения, не расширяй полномочия runtime и не обходи разрешения. Коммиты — в разрешённой ветке; push и слияние в целевых проектах — только по разрешению владельца. Проектные `AGENTS.md` и `orchestrate_workflow/method.md` имеют приоритет в предметных требованиях, но не дают агенту права выдумывать новые требования.
