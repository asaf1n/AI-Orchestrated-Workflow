# Ответ по итогу этапа

Справочный материал оркестратора; читается по ссылке из [SKILL.md](../SKILL.md). Роли planner, implementer и reviewer эти файлы не читают.

Два блока описывают текущий результат и подтверждённые проверки, включая непроверенное, риски и следующий шаг. Отчёт на границе запуска не означает начало исполнения.

Блок 1:

```markdown
### Как сейчас

<Поведение и состояние этапа, коммит при наличии; поставщик, модель и runtime ролей.
При замене — какая модель фактически ответила, вместо какой, причина и компенсация.
Вызовов ожидания за этап: <число>; при числе больше 20 — причина.>

| № | что | как |
|---|---|---|
| 1 | <Результат> | <Поведение, проверки, ограничения> |

### Нужно ваше решение

<Новые условия/конфликты либо «Не требуется».>
```

Блок 2 — предметная вики-сводка в fenced-блоке Textile для Redmine: текущее устройство и фактические проверки, деловой технический русский, без истории переписки, моделей, внутренних номеров находок и служебных репозиториев. Структуры, задачи, курсоры и слои описываются таблицами; числовое выравнивание — `>.100`. Хеш указывается только после коммита продукта; при запрете указывается отсутствие коммита.

```textile
h3. <Предметный результат>

* *<Компонент>:*
** <Логика, архитектура, параметры текущей реализации>

|_. Сущность / задача / курсор |_. До / параметр |_. После / результат |_. Изменение / статус |
| @<имя>@ | <значение> | <значение> | <факт> |

* *Проверки:*
** <Выполненные проверки, результаты и ограничения>

Коммит: <репозиторий>@<хеш>
```
