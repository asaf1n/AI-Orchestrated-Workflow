# Модели, инструменты и альтернативы

Справочный материал оркестратора; читается по ссылке из [SKILL.md](../SKILL.md). Роли planner, implementer и reviewer эти файлы не читают.

Выбирай модель и effort соразмерно риску и объёму: инструменты — для детерминированных сверок, достаточная менее затратная модель — для ограниченной обработки, сильная — для архитектуры и существенных контрактов. Роль самостоятельно выбор не меняет. Локальная LLM используется только при явном разрешении для извлечения и предварительной обработки со ссылками на источники; она не заменяет окончательные решения и независимую приёмку. Не создавай отдельный отчёт бюджета на каждый вызов.

Различай поставщика модели (Anthropic, OpenAI, Google), конкретную модель, runtime (встроенный Antigravity, agy, claude, codex) и канал квоты/подписки. Встроенный Claude в Antigravity — модель Anthropic через Antigravity, а не Gemini и не внешняя подписка Claude Code. Имя модели в промпте, имя файла мнения и `model: pro` не подтверждают точную модель или независимость квоты.

Используемые модели и runtime уточняются при запуске. Если выбор не уточнён и влияет на выполнение, его можно запросить в процессе; до ответа продолжается независимая разрешённая работа. При отсутствии специального ограничения роль наследует модель сессии. Выбор не записывается как предметное решение. Рабочий выбор и цепочка могут указываться в текущем spec.md. Роль не переключает себе модель; определения ролей не закрепляют конкретную модель. После изменения модели сессии пользователем не называй прежнюю модель текущей.

При прочих равных в Antigravity сначала используй доступную внутреннюю модель нужного поставщика, затем внешнюю. Требования к качеству, независимому контексту, доступам и изоляции важнее порядка. Ограничение пользователя «только внутренние модели» исключает внешние CLI. Не считай все внутренние модели Google: каталог `agy models` может содержать Gemini, Claude и GPT-OSS. Разрешённые значения Model/модельные tiers сверяй со схемой runtime; не приписывай `pro`, `flash`, `flash_lite`, `inherit` неизменные модели и поставщиков.

Ориентир по сильным сторонам моделей и рекомендуемым ролям, не требование: в конкретном вызове используется одна модель, а при недоступности или по обстоятельствам она заменяется любой подходящей. Проверенные runtime и сравнительная таблица находятся в README.md исходного репозитория, раздел «Текущие CLI и модели»; установленный комплект не требует копии README.

| Работа | Рекомендуется | Альтернатива 1 | Альтернатива 2 |
|---|---|---|---|
| Алгоритмы и SQL/PL-pgSQL | OpenAI GPT-6.1 Sol | Anthropic Claude Sonnet 5.5 | Google Gemini 3.8 Flash |
| Архитектурный рефакторинг | Anthropic Claude Opus 5.5 | OpenAI GPT-6 Astra | Google Gemini 3.8 Flash |
| Модульный рефакторинг | OpenAI GPT-6 Astra | Anthropic Claude Sonnet 5.5 | Google Gemini 3.8 Flash |
| Тяжёлые регламенты, логи и независимые оценки | Google Gemini 3.8 Flash | Anthropic Claude Sonnet 5.5 | OpenAI GPT-6.1 Sol |
| Вычитка документации | Anthropic Claude Sonnet 5.5 | Google Gemini 3.8 Flash | OpenAI GPT-6.1 Sol |

Это ориентир, а не доказательство доступности или качества. Доступность проверяй по каталогу и реальному ответу инструмента; фактическую замену называй в итогах. Явный выбор пользователя имеет приоритет перед таблицей.

Допустимые замены в рамках профиля: GPT-6 Astra вместо GPT-6.1 Sol для сложного SQL; Gemini 3.1 Pro вместо Flash для тяжёлого рассуждения; Haiku 4.5 для ограниченной вычитки, если качества достаточно. Не перечисляй варианты через `/` в ячейке действующего задания. При замене модели архитектурного/модульного рефакторинга желательно выполнить уже имеющиеся в проекте линтеры (`eslint`, `ruff`, `cargo clippy` по стеку), компиляцию и тесты; новые зависимости ради компенсации не добавляются. Подтверждай окончательное состояние результата и выполнение критериев разрешёнными проверками по контракту целевого сервиса. Для документации используй предметный словарь и исходные руководства. Для меньшего контекста предварительно фильтруй источники и разбивай их на связные части, сохраняя ссылки и ограничения. Не требуй публикации внутренней цепочки рассуждений: нужны проверяемое обоснование и доказательства.

При квоте или отказе используй следующий согласованный вариант модели и runtime; независимый поставщик нужен только при соответствующем критерии. Число резервов и поставщики определяются согласованным выбором и доступностью; обязательной цепочки из трёх поставщиков нет. Каждый выбранный вариант содержит одну модель; неиспользуемый резерв отмечается «не задан» или «не применяется». Смена модели внутри уже исчерпанного канала не считается независимым резервом без подтверждения runtime. Независимость компаний сама по себе не доказывает раздельную квоту внутренней подписки Antigravity.

Различай отказ модели, инструмента, канала квоты и целевой проверки. Не объявляй все модели недоступными по одному HTTP 429/503. Сохрани конкретный код и причину, оцени доступные альтернативы; при замене примени нужные проверки, словарь или фильтрацию контекста. Если все разрешённые варианты недоступны, сохрани точку продолжения и незавершённый результат; не выполняй продукт вместо роли. Недоступность обязательной проверки фиксируется отдельно. Замена модели сама по себе не является ни блокировкой проверки, ни приёмкой.

Причины различаются по фактическому ответу: HTTP 429/Insufficient Quota — квота или ограничение частоты; Context Exceeded — размер контекста; HTTP 503 — недоступность сервиса; ошибка запуска — инструмент. Antigravity CLI использует настроенный вход аккаунтом платформы; Claude Code и Codex — вход своего runtime. Их каналы и остатки не выводятся из общего имени Google или из наличия oauth-файла.

Модель подтверждается метаданными ответа или журналом инструмента. Если её нельзя подтвердить, пиши «запрошена <модель>; фактическая модель не подтверждена»; работа не отклоняется только поэтому. Не выдавай утверждение самой роли за метаданные. В итогах назови фактические модель, runtime и замену с причиной.

Для независимого мнения сохраняй доступный идентификатор вызова/сессии и ссылку на исходный ответ с метаданными без секретов. Проверяй отдельно выбранную параметром модель, модель фактического ответа и автоматический fallback. При замене переименуй обозначение мнения по фактическому поставщику; отменённый или неуспешный вызов остаётся невыполненным. Если критерий требует ответ конкретной модели или разных поставщиков, неподтверждённый поставщик либо модель не закрывает этот критерий; продолжай разрешённые независимые части, а зависимое решение обозначь как неподтверждённое. Это не означает отказа от пригодного результата обычного исполнения из-за отсутствия метаданных.
