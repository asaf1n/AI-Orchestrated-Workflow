# Выбор моделей и альтернатив

Модель выбирается по задаче и роли. Имена выпусков и линейки моделей не входят в протокол: конкретный model ID берётся из каталога runtime перед вызовом, если runtime поддерживает выбор модели.

| Класс | Назначение |
|---|---|
| `senior` | Планирование и архитектура при высокой неопределённости, ревью плана и рискованных изменений, арбитраж |
| `executor` | Реализация (код, SQL, тесты, конфигурации), разведка контекста, документация, локальные правки |
| `utility` | Лёгкие массовые операции: классификация, первичный разбор, простое извлечение; не для плана, архитектуры и приёмки |

Принцип: сильная модель с высоким `effort` — для плана и ревью рискованного; быстрая `executor` — для исполнения и локальных правок. Максимальный `effort` — когда результат зависит от легко упускаемых случаев (инварианты, конкурентность, миграции), а не по умолчанию. Подбирай достаточный профиль по цене ошибки, объёму контекста, скорости и квоте; обязательной очереди поставщиков и лестницы эскалации нет.

Модель и `effort` передавай, только если runtime их принимает. Runtime с фиксированным или управляемым профилем (составные режимы, Docker AI) используется со штатным профилем, если `method.md` не закрепляет модель. Составной режим (например, Antigravity Orchestrator) работает в одной сессии и не отменяет разделения ролей. `inherit` допустим, только если наследуемый профиль совпадает с нужным.

Reviewer отделяется новым контекстом, а не обязательно поставщиком. Другой поставщик класса `senior` оправдан при дорогой или необратимой ошибке (миграция схемы, изменение протокола, конкурентный доступ, транзакционные границы) или при конфликте оценок. Фактическую модель подтверждают метаданные runtime, а не самоназвание модели.

## Большой контекст

Если источники не помещаются в контекст Planner, Orchestrator до вызова выполняет read-only разведку (`task: context`) моделью с достаточным окном. Результат — список фактов с путями и способом проверки для поля «Источники» поручения Planner, без структуры плана.

## Сбой и эскалация

- При недоступности канала или исчерпании квоты переключись на альтернативный аккаунт, другой runtime той же модели или совместимый профиль того же класса, не повторяя выполненные операции. Это не требует согласования с пользователем.
- Если все разрешённые каналы исчерпаны, сообщи блокер и точку продолжения. Ожидание восстановления квоты — только по поручению пользователя.
- Известное исправление возвращается исполнителю без нового цикла Planner и Reviewer; архитектурный тупик или изменившаяся цель — Planner или более сильной модели.
- При ошибке среды не меняй модель произвольно и не обходи разрешения.
- После переключения канала укажи в итоге фактически использованный профиль.
