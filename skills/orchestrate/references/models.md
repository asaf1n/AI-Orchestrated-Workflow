# Выбор моделей

Модель, поставщик, runtime и `effort` — разные параметры. Выбирай достаточный профиль по сложности, риску, скорости, доступу и стоимости. Не устраивай цепочку смен моделей без фактической причины.

| Класс | Задачи |
|---|---|
| `senior` | Неоднозначная архитектура, сложное проектирование, серьёзные риски и независимая экспертная оценка |
| `executor` | Обычный код, тесты, документация, локальный рефакторинг и анализ |
| `utility` | Простое извлечение и массовая вспомогательная обработка |

Это ориентиры, не обязательные уровни. Составной Orchestrator в Antigravity — режим одной сессии; при достаточно простом запросе он может выполнить работу без запуска отдельных Planner, Implementer и Reviewer. Отдельное независимое ревью требуется только по запросу или при существенном риске.

Для локальной правки начни с доступного быстрого исполнителя. Для архитектуры и рискованного изменения выбери старшую подходящую модель; повышай `effort` при содержательной сложности, а не по названию роли. При явном требовании независимости используй отдельный контекст, при необходимости другого поставщика. Принудительный кросс-вендорный цикл не требуется.

Конкретные имена моделей и поддерживаемые параметры проверь в выбранном runtime, если эти настройки вообще доступны. Управляемые/fixed-profile режимы допустимы без `model ID` и `effort`. Модель не должна получать новые права ради ускорения.

При ошибке задания исправь исходную неоднозначность; при технической ошибке проверь фактическую причину. При нехватке квоты разрешён альтернативный канал без повторения выполненных операций; если каналов нет — сообщи блокер и точку продолжения. **Не ожидай часы сброса квоты автоматически**. Не делай повторный Planner или Reviewer только по факту смены модели.
