# Модели, инструменты и альтернативы

Справочный материал оркестратора; читается по ссылке из [SKILL.md](../SKILL.md). Роли planner, implementer и reviewer эти файлы не читают.

Выбирай поставщика, уровень модели (`обычный` или `лучшая модель`) и уровень рассуждений (`обычный` или `высокий`) соразмерно риску и объёму: инструменты — для детерминированных сверок, обычный уровень модели с обычным рассуждением — для ограниченной обработки, лучшая модель и высокий уровень рассуждений — для архитектуры и существенных контрактов. Роль самостоятельно выбор не меняет. Локальная LLM используется только при явном разрешении для извлечения и предварительной обработки со ссылками на источники; она не заменяет окончательные решения и независимую приёмку. Не создавай отдельный отчёт бюджета на каждый вызов.

Различай поставщика (Anthropic, OpenAI, Google), уровень модели и уровень рассуждений, конкретный идентификатор из каталога runtime (встроенный Antigravity, agy, claude, codex) и канал квоты/подписки. Встроенный Claude в Antigravity — модель Anthropic через Antigravity, а не Gemini и не внешняя подписка Claude Code. Имя модели в промпте, имя файла мнения и абстрактный псевдоним уровня в схеме субагента не подтверждают точную модель или независимость квоты.

Используемые поставщики, уровни моделей, уровень рассуждений и runtime уточняются при запуске; номера версий моделей в инструкциях не закрепляются, а конкретные идентификаторы берутся из актуального каталога среды. Если выбор не уточнён и влияет на выполнение, его можно запросить в процессе; до ответа продолжается независимая разрешённая работа. При отсутствии специального ограничения роль наследует модель сессии. Выбор не записывается как предметное решение. Рабочий выбор и цепочка могут указываться в текущем spec.md. Роль не переключает себе модель; определения ролей не закрепляют конкретную модель. После изменения модели сессии пользователем не называй прежнюю модель текущей.

При прочих равных в Antigravity сначала используй доступную внутреннюю модель нужного поставщика, затем внешнюю. Требования к качеству, независимому контексту, доступам и изоляции важнее порядка. Ограничение пользователя «только внутренние модели» исключает внешние CLI. Не считай все внутренние модели моделями Google: каталог `agy models` может содержать модели разных поставщиков (Google, Anthropic, OpenAI и открытые модели). Разрешённые параметры выбора модели и уровня рассуждений сверяй со схемой runtime; не приписывай абстрактным уровням схемы субагента (включая `inherit`) неизменные модели и поставщиков.

Ориентир задаётся без номеров версий через два уровня моделей — **обычный** (рабочая линейка поставщика: аналог Sol, Sonnet, Gemini Argon) и **лучшая модель** (старшая линейка: аналог Astra, Opus; при единой актуальной линейке поставщика, например Gemini Argon, роль старшего профиля выполняет высокий уровень рассуждений либо старшая модель текущего каталога) — и два уровня рассуждений (**обычный** и **высокий**). В конкретном вызове используется один профиль, а при недоступности или по обстоятельствам он заменяется любой подходящей альтернативой. Сводка поддерживаемых сред и уровней находится в README.md исходного репозитория, раздел «Текущие CLI и модели»; установленный комплект не требует копии README.

| Модульный рефакторинг | OpenAI, лучшая модель, рассуждение высокое | Anthropic, обычный, рассуждение высокое | Google, обычный, рассуждение высокое |

| Вычитка документации | Anthropic, обычный, рассуждение обычное | Google, обычный, рассуждение обычное | OpenAI, обычный, рассуждение обычное |

Это ориентир, а не доказательство доступности или качества. Доступность и точный идентификатор проверяй по каталогу runtime и реальному ответу инструмента; фактическую замену называй в итогах. Явный выбор пользователя имеет приоритет перед таблицей.

Допустимые замены в рамках профиля: повышение с обычного уровня до лучшей модели или с обычного до высокого уровня рассуждений для сложного SQL, нетривиальных инвариантов и тяжёлой оценки; облегчённый профиль поставщика с обычным рассуждением для ограниченной вычитки, если качества достаточно. Перед выдачей действующего spec.md выбранный уровень разрешается в конкретный идентификатор из текущего каталога runtime и параметр уровня рассуждений (либо явное наследование сессии); не перечисляй варианты через `/` в одной ячейке. При замене модели архитектурного/модульного рефакторинга желательно выполнить уже имеющиеся в проекте линтеры (`eslint`, `ruff`, `cargo clippy` по стеку), компиляцию и тесты; новые зависимости ради компенсации не добавляются. Подтверждай окончательное состояние результата и выполнение критериев разрешёнными проверками по контракту целевого сервиса. Для документации используй предметный словарь и исходные руководства. Для меньшего контекста предварительно фильтруй источники и разбивай их на связные части, сохраняя ссылки и ограничения. Не требуй публикации внутренней цепочки рассуждений: нужны проверяемое обоснование и доказательства.

При квоте или отказе используй следующий согласованный вариант модели и runtime; независимый поставщик нужен только при соответствующем критерии. Число резервов и поставщики определяются согласованным выбором и доступностью; обязательной цепочки из трёх поставщиков нет. Каждый выбранный вариант содержит одну модель; неиспользуемый резерв отмечается «не задан» или «не применяется». Смена модели внутри уже исчерпанного канала не считается независимым резервом без подтверждения runtime. Независимость компаний сама по себе не доказывает раздельную квоту внутренней подписки Antigravity.

Различай отказ модели, инструмента, канала квоты и целевой проверки. Не объявляй все модели недоступными по одному HTTP 429/503. Сохрани конкретный код и причину, оцени доступные альтернативы; при замене примени нужные проверки, словарь или фильтрацию контекста. Если все разрешённые варианты недоступны, сохрани точку продолжения и незавершённый результат; не выполняй продукт вместо роли. Недоступность обязательной проверки фиксируется отдельно. Замена модели сама по себе не является ни блокировкой проверки, ни приёмкой.

Причины различаются по фактическому ответу: HTTP 429/Insufficient Quota — квота или ограничение частоты; Context Exceeded — размер контекста; HTTP 503 — недоступность сервиса; ошибка запуска — инструмент. Antigravity CLI использует настроенный вход аккаунтом платформы; Claude Code и Codex — вход своего runtime. Их каналы и остатки не выводятся из общего имени Google или из наличия oauth-файла.

Фактическая модель подтверждается метаданными ответа или журналом инструмента; уровень рассуждений задаётся параметром вызова или профилем и подтверждается метаданными только в тех средах, которые его возвращают (отдельное протокольное поле в форме result.md для него не вводится). Если модель нельзя подтвердить, пиши «запрошена <модель>; фактическая модель не подтверждена»; работа не отклоняется только поэтому. Не выдавай утверждение самой роли за метаданные. В итогах назови фактические модель, runtime и замену с причиной.

Для независимого мнения сохраняй доступный идентификатор вызова/сессии и ссылку на исходный ответ с метаданными без секретов. Проверяй отдельно выбранную параметром модель, модель фактического ответа и автоматический fallback. При замене переименуй обозначение мнения по фактическому поставщику; отменённый или неуспешный вызов остаётся невыполненным. Если критерий требует ответ конкретной модели или разных поставщиков, неподтверждённый поставщик либо модель не закрывает этот критерий; продолжай разрешённые независимые части, а зависимое решение обозначь как неподтверждённое. Это не означает отказа от пригодного результата обычного исполнения из-за отсутствия метаданных.
