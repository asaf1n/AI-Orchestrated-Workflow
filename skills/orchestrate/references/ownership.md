# Принадлежность изменений

Orchestrator фиксирует границы поручений, при необходимости хранит оперативное состояние в `state.md` и коммитит принятый содержательный результат (при необходимости с краткой отметкой выполнения в плане без оперативных статусов и хронологии). Planner изменяет только назначенные материалы плана и назначенный отчёт; Implementer — порученные изменения и краткий результат (в файле лишь при необходимости); Reviewer — независимое заключение. Чужие правки не удаляются, не скрываются и не включаются в коммит.

До вызова и при восстановлении установи исходный HEAD, состояние index/worktree, последующие коммиты и реальные последствия незавершённых операций. Отсутствие отчёта или чистое рабочее дерево не доказывают приёмку. Не изменяй исходную точку задним числом.

Возврат Reviewer содержит конкретный дефект относительно исходных требований. Orchestrator оценивает его по существу и передаёт исправление роли по [SKILL.md](../SKILL.md) («Замечания»); сам вносит только механические правки. Коммит выполняется по завершении содержательной задачи в рамках разрешений. Push — только по прямому разрешению.
