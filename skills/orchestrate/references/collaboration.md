# Параллельное исполнение

Запускай параллельно только действительно независимую работу, если это уменьшает время или улучшает качество. Не создавай отдельные роли/слоты ради самого параллелизма.

- **Файлы:** раздельные границы записи либо отдельные worktree. Общий файл меняет один исполнитель за раз.
- **Ресурсы:** worktree не изолирует БД, порты, API и сервисы. Не допускай одновременно конфликтующие DDL, миграции и изменения общего состояния.
- **Контекст:** каждому делегированному исполнителю передавай собственное компактное поручение, исходные решения и необходимые пути без истории переписки.
- **Сборка:** после объединения изменений проверь конфликтующие участки и затронутые общие тесты, если интеграция на них влияет.

`runs/<id>/`, отдельные `spec.md`/`result.md`/`review.md` и фиксация владельцев в `state.md` нужны только при сложном длительном параллельном выполнении. Не требуется независимый Reviewer и отдельный коммит на каждую ветку автоматически.
