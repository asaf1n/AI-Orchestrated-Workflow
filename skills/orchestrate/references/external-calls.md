# Вызов внешних ролей

Запускай отдельную роль, только когда делегирование даёт реальную пользу. Для обычных правок Orchestrator может работать сам. Передавай конкретное поручение, релевантные файлы, решения и разрешённые пути; не пересылай историю всего чата.

Отдельный контекст рекомендуется для независимого Reviewer и делегированных задач. Проверяй по возможностям runtime, что запуск не наследует историю вызывающего чата. Не делай специальный тест с секретными метками и не сохраняй доказательства изоляции для **каждого** вызова. Если конкретный режим нарушает изоляцию и это существенно для задачи, выбери другой режим.

## CLI (ориентиры, уточняй по установленному `--help`)

| Runtime | Пример вызова |
|---|---|
| Claude Code | `claude -p [--model <id>] [--effort <level>] --permission-mode <policy>` |
| Codex | `codex exec [-m <id>] [-c model_reasoning_effort="<level>"] -s <sandbox>` |
| Antigravity CLI | `agy -p "<задание>" [--model <slug>] [--effort <level>] --output-format json` |
| Docker Agent | `docker agent run --exec --last --json [--model <provider/model>] --safety <policy> <agent-ref> "<задание>"` |

Встроенный субагент удобнее, если обеспечивает нужные инструменты, режим доступа и профиль. Не фиксируй конкретные модели в общем контракте. Для независимого ревью используй read-only доступ, где он возможен. Не отключай подтверждения/песочницу и не обходи отказ permissions.

Если локальный сервис недоступен в песочнице, другой режим допускается только при достаточных полномочиях пользователя или `method.md`; не меняй глобальные настройки ради одного вызова. Код 0 при отказе permissions не доказывает выполнения задачи. Применимые CLI-тесты и командные флаги уточняй по фактической среде, а не проверяй все интеграции заранее.

## Интерактивное планирование

Если пользователь **попросил отдельную сессию** Planner, открывай её в новом контексте и передавай только поручение. Возможные формы:

- Claude: `claude --permission-mode plan "/planner <поручение>"`.
- Codex: TUI с `/plan` и `$planner <поручение>`.
- Antigravity: `agy --mode=plan -i "/planner <поручение>"`.

Одобрение черновика внутри runtime не подменяет решение пользователя, но и не создаёт второй обязательный этап утверждения. Если пользователь сразу поручил реализацию, передавай план в исполнение без церемонии повторного запроса согласия.

## Внешний LLM-клиент и Antigravity

MCP-мост из `bridge/` направляет запросы во **владельческую** сессию `agy` и продолжает её через `--conversation <id>`. Внешний чат задаёт цель и решения, но не создаёт вторую параллельную оркестрацию. Не передавай секреты в промпте; удалённый доступ — за аутентифицированным TLS-шлюзом. Детали протокола и диагностики — [bridge/README.md](../../../bridge/README.md).

## Альтернативные аккаунты

Для отдельного вызова CLI можно выбрать профиль переменной окружения, не меняя глобальную конфигурацию:

| CLI | Переменная |
|---|---|
| Claude Code | `CLAUDE_CONFIG_DIR` |
| Codex | `CODEX_HOME` |

Учётные данные остаются внутри выбранного профиля. Проверь авторизацию штатной командой, не читай секреты и не передавай их агентам. Встроенный субагент использует аккаунт хост-сессии.

## Сбои

Сначала различай ошибку кода, прав, инструмента и квоты. Не дублируй уже выполненные операции и не пытайся обойти запрет. При квоте допустим разрешённый резерв; если он недоступен — верни краткий блокер и точку продолжения. Не запускай автоматическое многочасовое ожидание или периодические контрольные вызовы, если этого не просил пользователь.
