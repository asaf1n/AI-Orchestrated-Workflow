# Вызов ролей и параметры runtime

Вызов роли всегда получает новое независимое поручение, точный установленный `SKILL.md`, `AGENTS.md`, проектную привязку, критерии, версию файлов и границы доступа. Роли не выбирают себе модель и не запускают вложенную оркестрацию.

Выбери модель по [models.md](models.md), затем подходящий доступный runtime. Встроенный субагент допускается, если соответствует профилю, позволяет требуемую изоляцию и разрешения. `inherit` не подтверждает конкретную модель. Внешний CLI применяй при необходимости другого поставщика, effort или канала. Переключение runtime не должно обходить отказ прав доступа.

| Runtime | Вызов одного поручения |
|---|---|
| Claude Code | `claude -p --model <id> --effort <supported-level> --permission-mode <policy>` |
| Codex | `codex exec -m <id> -c model_reasoning_effort="<supported-level>" -s <sandbox>` |
| Antigravity CLI | `agy -p "<задание>" --model <slug> --output-format json` с `--effort <level>` только если поддерживается |

Роль Planner может записывать назначенные материалы; Implementer — назначенные файлы и результат; Reviewer — только назначенное заключение (либо итоговый ответ read-only). Для каждого CLI проверяй текущие `--help`, каталог моделей, код выхода, stdout, stderr, фактическую модель и влияние разрешений. Если разрешение отклонено, код 0 сам по себе не подтверждает выполнение.

Antigravity `invoke_subagent` использует только модели, доступные внутреннему субагенту; внешних поставщиков вызывай через их CLI. Допустимые значения модели проверяй по схеме установленного runtime; псевдонимы не означают конкретный выпуск модели или поставщика. Для внутреннего Reviewer указывай проверенные имена `tools` и исключай инструменты изменения продукта. Определения находятся в `.agents/agents/` (workspace) или `~/.gemini/config/agents/` (global). Составной Orchestrator — режим одной сессии с неизменяемым effort; он не заменяет независимого Reviewer.

## Внешний контроллер Antigravity

Поддерживается MCP-мост `bridge/` репозитория комплекта (описание — `bridge/README.md`; в установленный каталог навыков не копируется). Он передаёт из удалённого LLM-чата запрос в `agy -p "/orchestrate ..."` и продолжает зарегистрированную сессию через `--conversation <id>`. Единственный владелец плана — эта `agy`-сессия; внешний клиент не запускает вторую оркестрацию. Мост сериализует вызовы, сохраняет соответствие плана и conversation ID, проверяет завершение и сообщения об отказе.

Headless CLI использует заранее настроенные разрешения. Не отключай контроль подтверждений, не меняй авторизацию и не передавай секреты в промпте. Открытый HTTP без аутентификации запрещён; удалённый доступ требует защищённого TLS-шлюза. Для новых задач `/orchestrate` вызывается явно, так как навык может запрещать неявную активацию.

## Обработка сбоев

Сохрани частичный результат и реальный статус. Отказ модели, отказ runtime, нехватка квоты, блокировка permissions и падение предметной проверки требуют разных действий. Автоматическая замена не создаёт подтверждения обязательного профиля. Не повторяй завершённые операции без сверки их последствий.
