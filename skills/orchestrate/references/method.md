# Привязка проекта

Навыки `planner`, `orchestrate`, `implementer`, `reviewer` установлены в общем профиле и вызываются по имени. Полный протокол, формы состояния и шаблоны читаются из `references/` установленного навыка `orchestrate`. В проект референсы не копируются.

Этот файл оркестратор создаёт и адаптирует по `references/project-files.md` установленного навыка. В проекте используется один `orchestrate_workflow/method.md`; копии в каталогах планов и текущих сессий не создаются. Если установленный комплект недоступен, назови отсутствующий ресурс; не восстанавливай процесс по старым отчётам.

## Исполнение и ответ

После явного запуска утверждённого плана каждый этап проходит исполнение и независимое ревью. После приёмки оркестратор фиксирует результат и состояние этапа одним коммитом, проверяет его успешность и сразу переходит к следующему разрешённому этапу без повторного согласования. Явные ограничения поручения сохраняются; push разрешается отдельно. Вопросы задаются только при новых условиях или конфликтах, требующих решения пользователя. Возврат ревью исправляется в том же этапе в согласованных границах.

Ответ по итогу каждого этапа состоит из двух блоков:

1. «Как сейчас»: подтверждённое состояние, этап и коммит; затем таблица `№ | что | как` с изменениями и результатами проверок; затем «Нужно ваше решение» с новыми вопросами или строкой «Не требуется». Указать непроверенное и причины, открытые риски, следующий этап или завершение плана. Если решение не требуется, продолжить работу.
2. Вики-сводка в блоке кода `textile`: текущий результат и фактические проверки в нейтральном техническом стиле, без истории обсуждения и неподтверждённых выводов. Общая форма — в `references/templates.md` установленного навыка.

## Пути проекта

| Назначение | Место |
|---|---|
| Контракт проекта | `AGENTS.md` |
| Корень workflow | `orchestrate_workflow/` |
| Очередь и статус плана | `orchestrate_workflow/plans/<план>/00_summary.md` |
| Материал задачи и состояние этапов | `orchestrate_workflow/plans/<план>/<задача>.md` |
| Действующее задание | `orchestrate_workflow/<план>/spec.md` |
| Отчёт исполнителя | `orchestrate_workflow/<план>/result.md` |
| Независимое ревью | `orchestrate_workflow/<план>/review.md` |

`orchestrate_workflow/plans/` хранится в git. Каталог текущей сессии `orchestrate_workflow/<план>/` локальный и исключается по точному пути `/orchestrate_workflow/<план>/` через `.git/info/exclude`. Имя `plans` зарезервировано и не используется как имя плана.

Файлы выбираются только по точным путям и явным ссылкам. Task-файлами считаются только файлы, на которые ссылается `00_summary.md`. В каталоге текущей сессии протокольными являются только `spec.md`, `result.md`, `review.md`; другие локальные файлы читаются только при явной ссылке из материала задачи, задания или общего протокола.

## Проектные отклонения

Нет. Предметные источники, допустимые изменения и проверки определяет `AGENTS.md` и текущее задание этапа.
