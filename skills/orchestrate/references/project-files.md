# Подготовка файлов проекта

При порученной подготовке проекта, плана или его исполнении оркестратор сам обеспечивает файлы, необходимые последующим ролям. Пользователь задаёт цель и имя плана, а не создаёт вручную каталог workflow или заготовки инструкций. Статусный запрос остаётся чтением и не подключает проект.

## До передачи роли

1. Прочитать существующие AGENTS, CLAUDE, README, файлы workflow и определения ролей по точным путям. Сверить фактические команды проверки и ограничения; не назначать новую модель, доступы или зависимости.
2. При первом рабочем запуске в сессии проекта создать `orchestrate_workflow/references/`: скопировать все Markdown-ресурсы из `orchestrate/references/` установленного навыка. Протокол и зависимые документы хранятся под git внутри проекта; method и определения ролей ссылаются только на проектные документы. Сами навыки остаются установленными в общем профиле и вызываются по имени; их SKILL.md, метаданные среды, настройки и секреты в проект не копировать. Создать недостающий `orchestrate_workflow/method.md` из шаблона [method.md](method.md), адаптировав ссылки к проектному комплекту. Существующие документы не перезаписывать автоматически: обновление выполняется по поручению пользователя после сравнения с исходником, с сохранением проектных изменений и независимым ревью. Обновление установленного навыка само по себе проектные документы не меняет.
3. Если `AGENTS.md` отсутствует, создать контракт с ссылками на предметные источники проекта, проверенными командами проверок и действующими границами поручения. Неизвестное пометить неизвестным; не придумывать правила предметной области. Зафиксировать принадлежность инструкций оркестратору, продукта исполнителю, отчёта ревью reviewer. Существующий контракт сохранять; конфликт предъявить до зависимой работы.
4. Создать недостающие тонкие определения ролей для используемой среды по формам ниже. Они вызывают установленные навыки по имени и читают проектные документы относительными путями от корня проекта; не пересказывают протокол и не ссылаются на документы вне проекта. Для Claude отсутствующий `CLAUDE.md` содержит `@AGENTS.md`; существующий не перезаписывается.
5. При подготовке конкретного плана создать каталог `orchestrate_workflow/plans/<план>/`; planner получает точные пути и пишет очередь и материалы по [templates.md](templates.md). Пустой план для статусного запроса не создаётся.
6. Перед первым разрешённым вызовом создать `orchestrate_workflow/<план>/`, его точное исключение в `.git/info/exclude`, действующий spec и строки ожидания result/review. Исключение добавляется один раз, путь определяется через `git rev-parse --git-path info/exclude`. При восстановлении сначала прочитать существующие отчёты и последствия операций; не заменять их пустыми файлами только ради подключения.

Существующие файлы не заменяются заготовками. Проверка подключения — наличие нужных путей, разрешимость ссылок и чтение ими единого проектного комплекта без зависимости от профиля пользователя. Оркестратор выполняет эту проверку до вызова planner/implementer/reviewer. Настройки разрешений, секреты, инфраструктура и продукт не меняются ради подключения.

## Определения ролей

Создаются только недостающие определения используемой среды. Если проект уже предоставляет рабочие роли, использовать их. Родительские каталоги создаёт оркестратор. Ниже содержимое тонких файлов; предметные пути передаются в поручении.

### `.codex/agents/implementer.toml`

```toml
name = "implementer"
description = "Выполняет один этап по текущему spec.md."
developer_instructions = """
Используй установленный навык implementer. Прочитай orchestrate_workflow/method.md и следуй проектному протоколу. Корень проекта, режим и пути задания и отчётов передаёт оркестратор. Прочитай AGENTS.md и предметные источники из задания. Материал задачи с этапами находится под git по привязке проекта. Весь локальный контекст текущей сессии находится в каталоге, переданном оркестратором; spec.md, result.md, review.md — обязательные протокольные файлы. Не назначай себе другую модель. Не меняй файлы инструкций и плана, закреплённые за оркестратором. Не коммить.
"""
```

### `.claude/skills/orchestrate/SKILL.md`

```markdown
---
name: orchestrate
description: Ведёт явно запущенный план проекта по общему протоколу. Состояние этапов читает из материалов под git.
disable-model-invocation: true
---

Прочитай `orchestrate_workflow/method.md`, `orchestrate_workflow/references/protocol.md` и `AGENTS.md` этого проекта. Эта проектная обёртка использует созданные оркестратором документы процесса, без чтения документов вне проекта. Выполняй проектный протокол с путями из привязки.

Не создавай отдельный локальный план и копии заданий. На старте сверь материал задачи, git и каталог текущей сессии по `orchestrate_workflow/references/session-start.md`. Если запрошен статус, исполнение не запускай. Роли implementer и reviewer получай новым контекстом и текущей моделью, без своей модели. Принадлежность файлов из контракта сохраняется.
```
