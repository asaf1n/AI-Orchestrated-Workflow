# Подготовка файлов проекта

При порученной подготовке проекта, плана или его исполнении оркестратор сам обеспечивает файлы, необходимые последующим ролям. Пользователь задаёт цель и имя плана, а не создаёт вручную каталог workflow или заготовки инструкций. Статусный запрос остаётся чтением и не подключает проект.

## До передачи роли

1. Прочитать существующие AGENTS, CLAUDE, README, файлы workflow и определения ролей по точным путям. Сверить фактические команды проверки и ограничения; не назначать новую модель, доступы или зависимости.
2. Создать только недостающий `orchestrate_workflow/method.md` из [шаблона](method.md), адаптировав пути проекта и сохранив краткие инструкции исполнения и ответа. Общие protocol, project-files, session-start, runtimes, templates и шаблон method остаются в установленном навыке; `orchestrate_workflow/references/` не создаётся. Не копировать весь комплект, примеры, SKILL.md и метаданные навыков в проект. Существующий method сначала прочитать; менять его только в границах поручения, сохраняя проектные решения и настройки. При повторном подключении использовать те же файлы без дублей.
3. Если `AGENTS.md` отсутствует, создать контракт с ссылками на предметные источники проекта, проверенными командами проверок и действующими границами поручения. Неизвестное пометить неизвестным; не придумывать правила предметной области. Зафиксировать принадлежность инструкций оркестратору, продукта исполнителю, отчёта ревью reviewer. Существующий контракт сохранять; конфликт предъявить до зависимой работы.
4. Создать недостающие тонкие определения ролей для используемой среды по формам ниже. Они вызывают установленные навыки по имени, читают `AGENTS.md` и привязку проекта; полный протокол получают из навыка и не копируют его в определения ролей. Для Claude отсутствующий `CLAUDE.md` содержит `@AGENTS.md`; существующий не перезаписывается.
5. При подготовке конкретного плана создать каталог `orchestrate_workflow/plans/<план>/`; planner получает точные пути и пишет очередь и материалы по [templates.md](templates.md). Пустой план для статусного запроса не создаётся.
6. Перед первым разрешённым вызовом создать `orchestrate_workflow/<план>/`, его точное исключение в `.git/info/exclude`, действующий spec и строки ожидания result/review. Исключение добавляется один раз, путь определяется через `git rev-parse --git-path info/exclude`. При восстановлении сначала прочитать существующие отчёты и последствия операций; не заменять их пустыми файлами только ради подключения.

Существующие файлы не заменяются заготовками. Проверка подключения — наличие только требуемых для текущего проекта файлов, разрешимость ссылок и доступность установленного комплекта для всех ролей. Не создавать определения неиспользуемой среды, пустые планы, отчёты заранее, копии референсов и вторую привязку. При исправлении прежнего подключения сначала проверить ссылки и проектные дополнения в копиях; перевести потребителей на установленный комплект и сохранить необходимые проектные инструкции в method. Удаление старых файлов согласовать отдельно, если поручение его не разрешает. Оркестратор выполняет эту проверку до вызова planner/implementer/reviewer. Настройки разрешений, секреты, инфраструктура и продукт не меняются ради подключения.

## Определения ролей

Создаются только недостающие определения используемой среды. Если проект уже предоставляет рабочие роли, использовать их. Родительские каталоги создаёт оркестратор. Ниже содержимое тонких файлов; предметные пути передаются в поручении.

### `.codex/agents/implementer.toml`

```toml
name = "implementer"
description = "Выполняет один этап по текущему spec.md."
developer_instructions = """
Используй установленный навык implementer. Прочитай orchestrate_workflow/method.md и следуй общему протоколу установленного навыка. Корень проекта, режим и пути задания и отчётов передаёт оркестратор. Прочитай AGENTS.md и предметные источники из задания. Материал задачи с этапами находится под git по привязке проекта. Весь локальный контекст текущей сессии находится в каталоге, переданном оркестратором; spec.md, result.md, review.md — обязательные протокольные файлы. Не назначай себе другую модель. Не меняй файлы инструкций и плана, закреплённые за оркестратором. Не коммить.
"""
```

### `.claude/skills/orchestrate/SKILL.md`

```markdown
---
name: orchestrate
description: Ведёт явно запущенный план проекта по общему протоколу. Состояние этапов читает из материалов под git.
disable-model-invocation: true
---

Прочитай общий навык `~/.agents/skills/orchestrate/SKILL.md`, затем `orchestrate_workflow/method.md` и `AGENTS.md` этого проекта. Выполняй общий протокол с путями и проектными отклонениями из привязки. Референсы читай из установленного навыка, в проект их не копируй.
```
