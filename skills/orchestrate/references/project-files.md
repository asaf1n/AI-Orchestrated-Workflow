# Подготовка файлов проекта

При порученной подготовке проекта, плана или его исполнении оркестратор сам обеспечивает файлы, необходимые последующим ролям. Пользователь задаёт цель и имя плана, а не создаёт вручную каталог workflow или заготовки инструкций. Статусный запрос остаётся чтением и не подключает проект.

## До передачи роли

1. Прочитать существующие AGENTS, CLAUDE, README, файлы workflow и определения ролей по точным путям. Сверить фактические команды проверки и ограничения; не записывать модель в определения ролей, не добавлять доступы и зависимости.
2. Создать только недостающую проектную привязку `orchestrate_workflow/method.md` из [шаблона](method.md), адаптировав пути и проектные отклонения. Общие Markdown-ресурсы `orchestrate/references/` остаются в установленном навыке: каталог `orchestrate_workflow/references/` и копии протокола, шаблонов и SKILL.md в проекте не создаются. Существующую привязку не перезаписывать автоматически; по поручению об обновлении сохранить проектные дополнения и проверить результат независимым ревью. При удалении старых копий сначала сравнить их с общим комплектом, перенести значимые проектные отличия в method.md и исправить все действующие ссылки.
3. Если `AGENTS.md` отсутствует, создать контракт с ссылками на предметные источники проекта, проверенными командами проверок и действующими границами поручения. Неизвестное пометить неизвестным; не придумывать правила предметной области. Зафиксировать принадлежность инструкций оркестратору, продукта исполнителю, отчёта ревью reviewer. Существующий контракт сохранять; конфликт предъявить до зависимой работы.
4. Создать недостающие тонкие определения ролей для используемой среды по формам ниже. Они вызывают установленные навыки по имени, читают их общие ресурсы и проектную привязку; не пересказывают протокол и не копируют его в проект. Для Claude отсутствующий `CLAUDE.md` содержит `@AGENTS.md`; для Antigravity отсутствующий `GEMINI.md` содержит `@AGENTS.md`; существующие не перезаписываются.
5. При подготовке конкретного плана создать каталог `orchestrate_workflow/plans/<план>/`; planner получает точные пути и пишет очередь и материалы по [templates.md](templates.md). Пустой план для статусного запроса не создаётся.
6. Перед первым разрешённым вызовом создать `orchestrate_workflow/<план>/`, его точное исключение в `.git/info/exclude`, действующий spec и строки ожидания result/review. Исключение добавляется один раз, путь определяется через `git rev-parse --git-path info/exclude`. При восстановлении сначала прочитать существующие отчёты и последствия операций; не заменять их пустыми файлами только ради подключения.
7. При использовании внешних CLI (Codex, Claude Code) на Windows проверить доступность бинарников в `PATH`. Если `codex` отсутствует в `PATH`, проверить `%LOCALAPPDATA%\OpenAI\Codex\bin\*\codex.exe` и обеспечить доступ через shim `~/.local/bin/codex.cmd`. Для проектов с виртуальным окружением Python (`.venv`) подготовить передачу флага песочницы `--add-dir` с каталогом базового интерпретатора Python из `.venv/pyvenv.cfg`.

Существующие файлы не заменяются заготовками. Проверка подключения — наличие нужных путей, разрешимость ссылок и чтение ими общего установленного комплекта и проектной привязки. Оркестратор выполняет эту проверку до вызова planner/implementer/reviewer. Настройки разрешений, секреты, инфраструктура и продукт не меняются ради подключения.

Обновление общего комплекта выполняется по правилам [протокола](protocol.md#принадлежность-файлов): сначала независимое ревью исходников и затронутых привязок, затем перенос проверенной версии и сверка хешей. Права локального стенда берутся из действующего контракта проекта; подключение навыков не вводит дополнительные запреты или повторные согласования разрешённых операций.

## Определения ролей

Создаются только недостающие определения используемой среды. Если проект уже предоставляет рабочие роли, использовать их. Родительские каталоги создаёт оркестратор. Ниже содержимое тонких файлов; предметные пути передаются в поручении.

### `.codex/agents/implementer.toml`

```toml
name = "implementer"
description = "Выполняет один этап по текущему spec.md."
developer_instructions = """
Используй установленный навык implementer. Если установленный навык недоступен для чтения, назови путь и остановись; процесс по привязке и прежним отчётам не восстанавливай. Прочитай orchestrate_workflow/method.md и следуй общему протоколу установленного навыка и проектной привязке. Корень проекта, режим и пути задания и отчётов передаёт оркестратор. Прочитай AGENTS.md и предметные источники из задания. Материал задачи с этапами находится под git по привязке проекта. Весь локальный контекст текущей сессии находится в каталоге, переданном оркестратором; spec.md, result.md, review.md — обязательные протокольные файлы. Не переключай себе модель; модель роли задаёт оркестратор. Не меняй файлы инструкций и плана, закреплённые за оркестратором. Не коммить.
"""
```

### `.claude/skills/orchestrate/SKILL.md`

```markdown
---
name: orchestrate
description: Ведёт явно запущенный план проекта по общему протоколу. Состояние этапов читает из материалов под git.
disable-model-invocation: true
---

Используй установленный навык `orchestrate`. Если установленный навык недоступен для чтения, назови путь и остановись; процесс по привязке и прежним отчётам не восстанавливай. Прочитай `orchestrate_workflow/method.md` и `AGENTS.md` этого проекта. Общие правила и ресурсы читай из установленного навыка; проектная привязка задаёт пути и отклонения.

Не создавай отдельный локальный план и копии заданий. На старте сверь материал задачи, git и каталог текущей сессии по началу сессии из установленного навыка `orchestrate`. Если запрошен статус, исполнение не запускай. Роли implementer и reviewer получай новым контекстом; поставщика и модель роли выбирай по общему протоколу. Принадлежность файлов из контракта сохраняется.
```
