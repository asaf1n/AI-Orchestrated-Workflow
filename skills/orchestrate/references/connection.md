# Подключение проекта

Справочный материал оркестратора; читается по ссылке из [SKILL.md](../SKILL.md). Роли planner, implementer и reviewer эти файлы не читают.

Подготовка порученного проекта/плана включает необходимые файлы без отдельного разрешения на каждый; статусное чтение их не создаёт. Сначала прочитай существующие AGENTS, CLAUDE, GEMINI, README, привязку и роли. Создавай только недостающее, сохраняй пользовательские настройки и предметные правила. Не меняй доступы, секреты, инфраструктуру и зависимости ради подключения.

Создай одну привязку по форме ниже. Не создавай orchestrate_workflow/references, копии SKILL.md и дополнительные method.md. При удалении старых копий сначала сопоставь содержимое, перенеси проектные отличия в привязку, исправь действующие ссылки. В контракте зафиксируй предметные источники, проверенные команды и принадлежность файлов; неизвестное не придумывай. Для Claude отсутствующий CLAUDE.md, для Antigravity отсутствующий GEMINI.md содержит `@AGENTS.md`; существующие сохраняются.

Определения ролей — тонкие файлы `.codex/agents/<роль>.toml`, `.claude/agents/<роль>.md` либо определения текущего API Antigravity. Они читают точный установленный SKILL.md роли и привязку, получают пути от оркестратора; модель наследуется, инструментальный доступ не шире поручения. Файл Antigravity нельзя объявлять рабочим только по аналогии с Claude: проверь обнаружение и схему. Новые папки и определения заранее не создаются.

Для роли Codex используй `name`, `description`, `developer_instructions`; для Claude — frontmatter `name`, `description`, `tools`, `model: inherit` и тело с чтением установленного навыка. Внешнему read-only reviewer доступны инструменты чтения и разрешённых проверок, а заключение сохраняет вызывающий инструмент.

## Формы тонких ролей

Подставь `<роль>` как implementer или reviewer и предметные пути в поручение. В Codex файл `.codex/agents/<роль>.toml` имеет форму:

```toml
name = "<роль>"
description = "<Один этап по spec.md либо независимое ревью результата>"
developer_instructions = """
Прочитай точный установленный SKILL.md роли <роль>, затем AGENTS.md,
orchestrate_workflow/method.md и источники поручения. Корень, режим, исходную
версию и пути spec.md/result.md/review.md передаёт оркестратор.
При недоступном навыке назови точный путь; процесс из старых отчётов не восстанавливай.
Не меняй модель, инструкции, план и чужие правки. Не коммить.
Исполнитель работает только в перечне spec.md и приносит собственный result.md.
Ревьювер не исправляет продукт; если заключение запрошено итоговым ответом,
файлы не пишет и возвращает полную форму своего SKILL.md без посторонних пояснений.
"""
```

Для Codex planner используется отдельный `.codex/agents/planner.toml`:

```toml
name = "planner"
description = "Готовит новый план или существенный пересмотр; исполнение не запускает"
developer_instructions = """
Прочитай точный установленный planner/SKILL.md, AGENTS.md, пути и отклонения
orchestrate_workflow/method.md и предметные источники поручения.
Корень, режим, исходную версию и пути материалов плана передаёт оркестратор.
Меняй только порученные очередь и материалы задач, сохраняй чужие правки.
Не утверждай план, не запускай исполнение, не меняй инструкции и модель, не коммить.
При недоступном навыке назови точный путь; старый отчёт не заменяет навык.
"""
```

В Claude `.claude/agents/implementer.md`:

```markdown
---
name: implementer
description: Выполняет один этап по текущему spec.md.
tools: Read, Edit, Write, Grep, Glob, Bash
model: inherit
---

Прочитай установленный implementer/SKILL.md, AGENTS.md, привязку и источники
поручения. Точные корень, spec.md, result.md и ресурсы передаёт оркестратор.
Работай только по spec.md, сохраняй чужие правки. Не меняй модель,
инструкции и план. Не коммить. При недоступном навыке назови точный путь.
```

В Claude `.claude/agents/reviewer.md`:

```markdown
---
name: reviewer
description: Независимо проверяет план, инструкции или результат этапа.
tools: Read, Grep, Glob, Bash, Write
model: inherit
---

Прочитай установленный reviewer/SKILL.md, AGENTS.md, привязку, материал
и входы поручения. Корень, режим, исходную версию и пути передаёт оркестратор.
Не меняй модель, продукт, инструкции, план и чужие правки. Не коммить.
Пиши только в назначенный путь заключения; если заключение запрошено
итоговым ответом, файлы не пиши и верни полную форму своего навыка.
При недоступном навыке назови точный путь; старый отчёт его не заменяет.
```

В Claude `.claude/agents/planner.md`:

```markdown
---
name: planner
description: Готовит новый план или существенный пересмотр; исполнение не запускает.
tools: Read, Grep, Glob, Bash, Write, Edit
model: inherit
---

Прочитай установленный planner/SKILL.md, AGENTS.md, привязку и источники
поручения. Корень, режим и пути передаёт оркестратор. Меняй только названные
материалы плана, сохраняй чужие правки. Не утверждай план, не запускай
исполнителя, не меняй модель, не коммить. При недоступном навыке назови точный путь.
```

Встроенному reviewer доступ Write ограничивается назначенным путём заключения; внешнему read-only reviewer запись не даётся. Для Antigravity используемые инструменты и поля задаются его текущим API; форма тела роли та же: точное чтение навыка и привязки, предметные входы, граница записи, независимый вердикт и наследование модели. При существующих рабочих определениях используй их, не создавай ещё одну копию.

Если workspace-скилл с именем orchestrate необходим для обнаружения, его тонкое тело прямо читает глобальный `~/.agents/skills/orchestrate/SKILL.md` или фактический глобальный путь runtime и проектную привязку. Оно не вызывает само себя по имени. Не создавай второй wrapper в другом каталоге того же runtime; фактический путь обнаруженного SKILL.md проверяется при обновлении. Метаданные пользователя сохраняются.

Форма workspace-скилла в `.agents/skills/orchestrate/SKILL.md` для Antigravity либо в `.claude/skills/orchestrate/SKILL.md` для Claude:

```markdown
---
name: orchestrate
description: Вызывает глобальный навык оркестрации с привязкой проекта.
disable-model-invocation: true
---

Прочитай напрямую ~/.agents/skills/orchestrate/SKILL.md, затем AGENTS.md
и orchestrate_workflow/method.md проекта. Повторный вызов по имени не заменяет
чтение глобального файла. Если он недоступен, назови точный путь и причину.
Действуй в границах поручения; статус исполнение не запускает.
```

При подготовке конкретного плана planner создаёт его каталог и материалы по своей форме. Перед первым разрешённым вызовом этапа создай отсутствующий каталог сессии и добавь точное `/orchestrate_workflow/<план>/` в локальный info/exclude, полученный через `git rev-parse --git-path info/exclude`. Каталог plans не исключается. При восстановлении прежние отчёты не заменяются пустыми файлами ради подключения.

## Форма привязки method.md

```markdown
# Привязка проекта <имя>

Оркестратор читает orchestrate/SKILL.md, остальные роли — собственные SKILL.md.
План, выполнение и независимая приёмка разделены между planner, implementer и reviewer.
В проект общие правила и формы не копируются; здесь задаются пути и отклонения.

## Пути проекта

| Назначение | Место |
|---|---|
| Контракт | AGENTS.md |
| Очередь и статус | orchestrate_workflow/plans/<план>/00_summary.md |
| Материал задачи | orchestrate_workflow/plans/<план>/<задача>.md |
| Задание / результат / ревью этапа | orchestrate_workflow/<план>/spec.md, result.md, review.md |
| Ревью плана или инструкций | orchestrate_workflow/<план>/review_plan.md |

plans хранится в git; каталог сессии исключён по точному пути через info/exclude.
Файлы выбираются по явным ссылкам. plans — зарезервированное имя.

## Проектные отклонения

<Только подтверждённые предметные дополнения; без повторения общего протокола.>
```
