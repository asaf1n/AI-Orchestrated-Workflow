# Подключение проекта

Достаточно проектного `AGENTS.md`. `orchestrate_workflow/method.md` добавляют, если нужны местные пути, профили, ограничения или формат отчёта. Не копируй общий протокол в проект.

Типовые (необязательные) пути:

| Материал | Путь |
|---|---|
| Длительный план | `orchestrate_workflow/plans/<имя>/` |
| Точка продолжения | `orchestrate_workflow/<имя>/state.md` |
| Передача отдельному исполнителю | Сообщение либо `spec.md` |
| Результат и ревью | Сообщение; `result.md`, `review.md` и `review_plan.md` только при необходимости |

План и важные проектные решения можно версионировать в Git. Оперативный `state.md` и временные отчёты обычно хранят вне Git. Существующая структура проекта не требует миграции.

## Определения ролей

Для Codex: `.codex/agents/<роль>.toml`. Для Claude Code: `.claude/agents/<роль>.md`. Для Antigravity: `.agents/agents/<роль>.md` либо фактически поддерживаемый глобальный каталог. Адаптер должен только указывать на установленный `SKILL.md` и границу задания; не дублируй протокол.

Модель и `effort` задают при необходимости. Реальные возможности и пути проверяй по установленному runtime, не по примерам. Reviewer читает порученные материалы и не меняет продукт.

Пример `method.md`:

```markdown
# Привязка проекта

## Пути и источники
<Только отклонения от обычной структуры>

## Права и ограничения
<Только действующие требования>

## Проверки / отчёт
<Только проектно-специфичное>
```
