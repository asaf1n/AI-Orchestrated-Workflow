Прочитай [протокол](references/protocol.md) и контракт `AGENTS.md`, затем привязку проекта `orchestrate_workflow/method.md`. Выполняй протокол. Привязка задаёт пути, а не вторую версию правил.

При явно порученном первоначальном подключении проекта создай отсутствующий `orchestrate_workflow/method.md` из [общего шаблона](references/method.md), учитывая пути и ограничения существующего `AGENTS.md`. Существующие файлы не перезаписывай; конфликтующие настройки сообщи. Общие `protocol.md`, `session-start.md`, `runtimes.md` и `templates.md` в проект не копируй. Если поручения на подключение нет, отсутствие привязки — препятствие: назови путь и не восстанавливай процесс по старым отчётам. Запрос статуса или обсуждение не разрешают создание файлов. Подключение не создаёт пустые каталоги планов или сессий и не запускает этапы. Если поручено только подключение, сообщи о созданной или существующей привязке и конфликтах и заверши поручение; наличие плана для этого не требуется.

При вызове по конкретному плану на старте сверь статус плана, материал задачи, git и каталог текущей сессии по [началу сессии](references/session-start.md). Новый этап запускается только у утверждённого плана. Статусный запрос исполнение не запускает.

Для ролей используй навыки planner, implementer и reviewer, новый контекст и текущую модель. Модель роли не переопределяй. Контракт принадлежности файлов сохраняется: инструкции, привязку и каталог плана правит оркестратор.

Не создавай отдельный локальный план и копии заданий. Весь локальный контекст текущей сессии находится в каталоге, заданном привязкой проекта; единственное действующее задание — его `spec.md`.

Перед первым разрешённым вызовом этапа создай отсутствующий локальный каталог `orchestrate_workflow/<план>/` по привязке и добавь его точный путь `/orchestrate_workflow/<план>/` в локальный `.git/info/exclude`, если его там нет. Путь файла exclude определяй через `git rev-parse --git-path info/exclude`; каталог `orchestrate_workflow/plans/` не исключай. `spec.md`, `result.md` и `review.md` формируй по [действующим шаблонам](references/templates.md). Исполнитель и reviewer получают готовую привязку и точные пути; самостоятельно проект не подключают.
